# Git —— 从第一性原理出发

如果只讲第一性原理，Git 本质上只做三件事：

- 记录一组文件在某一时刻的快照
- 用一条有父子关系的历史链把这些快照连起来
- 在不同仓库之间同步这些快照和指针

你真正要掌握的，不是几十个命令，而是这几个对象和它们怎么变化。

一张脑图

- 工作区：你眼前正在编辑的文件
- 暂存区：你准备放进“下一次提交”的文件清单
- 本地仓库：.git 里的历史数据库
- 提交 commit：一次完整快照
- 分支 branch：指向某个提交的名字
- HEAD：你当前站在哪个分支/提交上
- 远端 origin/upstream：别人的仓库或服务器上的仓库

你可以把 Git 理解成：

- 工作区 = 草稿纸
- 暂存区 = 你准备交卷的内容
- 提交 = 一次正式存档
- 分支 = 某条时间线的标签
- 远端 = 另一台机器上的同类档案馆

---

## 1. 最核心的第一性原理

### 1) Git 记录的是“快照”，不是“补丁”

每次 commit，Git 记录的是“这一刻整个项目长什么样”。

所以你要养成的思维是：

- 我现在要不要保存一个完整状态
- 我这次提交是不是一个独立、清晰、可回滚的状态

### 2) 分支不是“副本”，只是“指针”

很多新手以为分支复制了一份代码。不是。

分支本质上只是：

- “当前这条线最新提交是谁”的一个名字

所以创建分支很便宜，因为只是新建一个指针。

### 3) commit 不等于“当前工作区”

当前工作区可以是乱的。
只有 commit 才是正式历史。

所以永远区分三层：

- 你改了，但还没告诉 Git：工作区修改
- 你告诉 Git 下次要保存哪些：暂存区
- 你真的存档了：提交

---

## 2. 你必须彻底理解的三层结构

### 工作区

你真实编辑文件的地方。

### 暂存区

“下一次提交要装进去什么”。

### 本地仓库

真正的历史。

---

## 3. 一个直白建议

不要把 Git 当“命令集合”学。
要把它当“状态机”学。

每个命令，本质上只是在改下面五样东西之一：

- 工作区
- 暂存区
- 提交对象
- 分支指针
- 远端分支指针

一旦你按这个角度理解，Git 会突然变简单。

在开始之前，或许你可以花 1-2 个小时玩一玩 [在线图形化Git教程](https://learngitbranching.js.org/?locale=zh_CN) ，以对Git在逻辑上有一个初步的了解。
